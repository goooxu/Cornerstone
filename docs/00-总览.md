# 总览

## 为什么是这个设计

项目的四条硬约束各自把设计逼向一个方向：

| 约束 | 推出的结论 |
|---|---|
| 不用棋谱 | 只能自博弈强化学习。连**评测基线**也必须由规则构造（随机 / 贪心 / 纯 rollout MCTS），不能拿棋谱当测试集 |
| 不复用开源 Blokus AI 结构 | 网络结构自研。常见开源实现是卷积 ResNet，我们走「FP8 GEMM 为主体」的路子，天然分道 |
| 主权重 FP8 | 优化器直接在 FP8 权重上更新（MXFP8 + 随机舍入）。**必须有 BF16 对照跑**，否则「FP8 无损」没有依据 |
| 压满 CPU 与 GPU | CPU 跑 MCTS 与着法生成，GPU 跑批量推理与训练，用共享内存攒批把两者流水重叠 |

## 关键设计决策

### 动作空间 = 91 × 196 = 17836

21 枚棋子按「4 旋转 × 2 镜像」展开去重后恰好 **91 个不同朝向**（生成时会断言这个数）。
动作编码为 `orientation * 196 + 包围盒左上角格号`，正好对应策略头的 `91×14×14` 张量。
越界与非法动作用 mask 屏蔽。

### 价值头是 WDL 三分类，不是 tanh 标量

本项目的胜负判定是「占格多者胜、相同为和局」，和局是**真实且不罕见**的结果——
随机对局下和局率约 4.5%，强度接近的对手之间只会更高。
tanh 标量没法区分「这是和棋局面」和「胜负各半的混沌局面」，所以价值头用 WDL 三分类 softmax，
MCTS 回传用 `P(W) − P(L)`。

### 特征里不放手数 ply

见 [docs/02-引擎设计.md](02-引擎设计.md) 的对称群一节：`ply` 的奇偶性和座位相关，
会让 ROT180 / ANTIDIAG 两个增广产生分布外样本。改用座位无关的「己方/对方占格数」，
信息量不比 ply 少，且四个对称变换全部严格自洽。

### FP8 既不省显存，实测也没怎么提吞吐

这一条和最初的设想相反，实测数据摆在这里（详见 [06](06-FP8主权重.md)）：

- **不省显存**：TE 同时保留行/列两套布局，每参数 2.06 字节，比 BF16 的 2 字节还多
- **不太提吞吐**：D=256 时 1.00×，加宽到 169M 参数也只有 1.06×。
  MXFP8 每层都要重扫激活求块 amax，196 个 token 的 GEMM 摊不薄这笔开销

FP8 主权重这条路是**正确且可用**的（数值上有测试守着，尤其是随机舍入那条），
但它不是这个项目的性能杠杆。真要提吞吐得靠 `torch.compile` 融合、CUDA Graph、加宽模型。

## 已完成部分的实测数据

### 引擎吞吐（随机对局，全程 C++、释放 GIL）

| 线程 | 对局/s | 着法生成/s |
|---:|---:|---:|
| 1 | 3,165 | 85,810 |
| 16 | 50,252 | 1,362,863 |
| 64 | 201,874 | 5,474,436 |
| 128 | 380,458 | 10,319,128 |

128 线程相对单线程加速比 **120×**（约 94% 并行效率）。

含义：着法生成不会是瓶颈。按 200 次模拟/手估算，CPU 侧能支撑的搜索量远超 GPU 侧
能提供的推理吞吐——瓶颈落在 GPU，这是正确的位置。

### 随机对局的统计特征

- 平均每局 **27.1 手**（远小于上限 42 手，说明随机走子很早就把自己堵死）
- 先手胜率 **0.541**，和局率 **0.045**
- 平均占格数：先手 55.1 / 后手 53.4（满分 89）

先手优势 4 个百分点，arena 评测必须交换先后手。

### 正确性

- 规则单测 146 项全绿
- 与**完全独立的朴素实现**交叉比对 **1,000,020 个局面，零不一致**（耗时 192.6s）

### 网络棋力（BF16 长跑，step 4000）

对 `greedy-area` 200 局：**162 胜 / 5 和 / 33 负，得分率 0.823**，
Elo 差 +266 → **绝对 Elo ≈ 715**。

放回阶梯里看，此时网络已经站到 `flat-mcts-1k`（733）附近，
远超 `greedy-area`（448）与 `flat-mcts-256`（537）。曲线仍在上升。

### 自博弈吞吐（14.2M 参数，64 次模拟/手）

| 配置 | 评估/s | 等效局/s |
|---|---:|---:|
| 最初 | 7,508 | 4.3 |
| 单卡（compile + 引擎 32 线程 + 并行 2048） | 56,859 | 32.8 |
| **四卡** | **170,715** | **98.4** |

合计 **22.7×**。瓶颈换过三次位置，过程见 [docs/07-性能调优.md](07-性能调优.md)。

### 基线阶梯（每对 400 局）

| 智能体 | Elo | ± |
|---|---:|---:|
| `flat-mcts-4k` | 991.6 | 12.1 |
| `greedy-mobility` | 836.7 | 8.8 |
| `flat-mcts-1k` | 733.2 | 8.0 |
| `flat-mcts-256` | 537.0 | 7.9 |
| `greedy-area` | 448.4 | 8.3 |
| `random` | 0.0 | 24.1 |

六档严格单调、相邻间隔均超过 85 Elo，可以拿来给网络定强度。
调好权重的 `greedy-mobility` 抵得上上千次随机 rollout —— 说明随机 rollout 在 Blokus 上
信号很弱，这正是需要价值网络的地方。细节见 [docs/03-基线与评测.md](03-基线与评测.md)。
