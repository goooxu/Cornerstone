# 已知问题与后续

## 已知限制

### FP8 用不了 `torch.compile`

开着 compile 跑 FP8，先冒 TE 自定义算子的 graph break 告警，
接着编译出来的图直接 CUDA 非法访存。`TrainConfig.resolve()` 会自动关掉 compile 并打印提示。

代价是 1.8×。**不是 FP8 算得慢，是它挡住了这条加速路。** 详见 [06](06-低精度训练.md)。

> 曾经以为还有第二条限制「同进程 FP8 只能用一张卡」。**那是误判** ——
> 真正的条件是「调用 TE 时当前 CUDA 设备要与张量设备一致」。
> 护栏现在放在 `CornerNet.forward` 里，FP8 多卡工作正常。

### 一条没查到源头的告警（已结，触发条件消失）

FP8 训练启动时，TE 曾会发**一次** `You are using quantized weights without
quantized compute`，出现在两次自检之后、第一轮自博弈期间，一直没查到源头。

改成标准配置（fp32 主权重 + FP8 GEMM）之后，权重不再是量化张量，
**这条告警的触发条件本身不存在了**，本条关闭。

它留下的教训比问题本身值钱：探针不能挂在告警上。旧的 `verify_fp8_compute()`
正是靠捕获这条告警判断降级的，而告警消失之后它会**静默退化成恒真** ——
一个永远说 OK 的探针比没有探针更糟。现在改成直接查 TE 的状态
（`fp8.fp8_gemm_active()`，见 [06](06-低精度训练.md)），
并由 `test_probe_distinguishes_enabled_from_disabled` 守着它的分辨力。

### Web 试玩的高难度档偏慢

单局面搜索的批大小恒为 1，每次模拟都要单独跑一次前向。
「极难」档 800 次模拟约 4.6 秒。要压下来得在单棵树里用 virtual loss
并行展开若干叶子。见 [05](05-web试玩工具.md)。

### 自博弈与训练是严格轮流的

现在一轮里先跑自博弈再训练，两个阶段不重叠。好处是简单、可复现、
权重版本没有歧义；代价是任一阶段跑的时候另一类资源在闲着。

### 评测会自己吃掉大半墙钟（已修一半）

`evaluate_vs_baseline()` 原本**没有 `engine_threads` 参数**，构造
`SelfPlayDriver` 时不传，于是吃默认值 `1` —— 在 144 核的机器上单线程跑树搜索。
对手是 `flat-mcts-4k`（每手 4096 次 rollout）时，200 局要跑约 25 分钟。
BF16 那条正式训练里 50 次周期评测因此吃掉 **21 小时**墙钟，
比训练加自博弈加起来（15.1 小时）还多。

参数已补上并由 `tools/train.py` 透传 `cfg.engine_threads`。**但另一半还没修**：
基线在第 5.2 万步（整个训练的 26% 处）就被打穿了，此后 38 次评测的得分率
全部落在 0.98–1.00 的二项噪声里，分辨不出任何提升 —— 评测应当在得分率稳定
超过某个阈值后**自动换更强的锚点**，而不是继续对着打穿了的基线刷分。

### 单条边换算 Elo 会饱和成假数

`elo_from_score_rate` 把胜率钳到 `1−1e-9`，所以 200:0:0 换算出来是
`−400·log10(1e-9) = +3600`。BF16 那条跑的 `eval_elo_abs` 里有 6 个点是
4591.6，全是这么来的，画曲线/引用时必须剔除。

想量「强过全部规则基线之后还有多强」，只能让**每条比较边都尽量不饱和**，
再靠连通图把尺度传过去 —— 这是 `tools/net_arena.py` 的做法：
规则之间全打锚零点、网络之间只打相邻里程碑、早期网络负责搭桥，
最后一次 Bradley-Terry 联合拟合。

### 训练到 20% 就见顶，之后一路退（最大的未解问题）

两轮独立训练、四条腿，结论完全一致：

| | 峰值 | 终点相对峰值 |
|---|---:|---:|
| `ab-bf16` | 90,230 步 | −36 |
| `ab-fp8` | 80,252 步 | −82 |

**80~89% 的棋力增长在前 4 万步（总量的 20%）就拿到了**，之后 16 万步不但没有
提升，还倒退了 36~82 分。这比精度选型重要得多 —— 在它解决之前，
FP8 与 BF16 差的那 30 分意义有限。

已经排除掉的两个解释：

- **不是自博弈分布塌缩**。`ab-bf16` 的先手胜率涨到 0.992（价值头在学常数），
  而 `ab-fp8` 全程稳在 0.85 从未塌缩 —— 两条照样在同一位置见顶，
  且没塌缩的那条**掉得更多**。
- **不是缺少外部参照**。试过对手池（一半的自博弈对局去打本次运行自己的历史
  里程碑，每轮重采）：峰值仍在 90,286、终点低 40 分，与不带池的运行几乎逐位
  重合。顶尖档交叉对打 6,400 局只有 +9~13 Elo，BF16 组的置信区间还跨过 0。
  唯一确定改变的是 **loss 形状**（单调降到终点、不再触底回升），棋力曲线的任何
  特征都没变 —— 又一次说明 loss 与棋力脱钩。实现已回退。

**目前剩下的主要嫌疑是探索不足**：每手只有 64 次模拟、`temperature_plies=12`
相对 30 手的对局偏短、没有 Dirichlet 噪声这类显式探索项。有一条反直觉的线索：
把采样温度从 12 手延到全程 30 手，自博弈先手胜率不降反升（0.880 → 0.905），
说明现有的探索机制可能根本没在起作用 —— 值得先查清这一点再加旋钮。

### 先手优势比想象的大，而且随棋力放大

用「同一开局双方各执先一次」的配对口径实测（400 局）：

| | 先手胜率 |
|---|---:|
| `random` | 0.535 |
| `greedy-mobility` | 0.585 |
| `flat-mcts-1k` | **0.420**（后手反而占优） |
| 网络（峰值档） | **0.755** |

所以文档里早期那句「先手优势约 4 个百分点」只适用于弱规则智能体，
强网络下是 **25 个百分点**。但 0.755 远不是必胜，`flat-mcts-1k` 甚至反向 ——
**先手必胜**这个说法不成立。

由此得到一个比「先手胜率 > 0.9」更干净的塌缩判据：
**自博弈先手胜率 − 该档在配对口径下的先手胜率**。前者含搜索放大与开局不配对，
后者是客观优势，差值拉到 0.2 以上才说明分布真的塌了。
（`ab-bf16` 终点档：配对 0.705、自博弈 0.975，差 0.27。）

### 已发布的 A/B 同时动了三个变量，30.6 Elo 不能归因给 FP8

`ab-bf16` / `ab-fp8` 那次对照声称测的是「FP8 vs BF16」，实际上两条腿有三处不同：

1. **主权重格式** —— FP8 腿是 MXFP8，没有 fp32 master
2. **优化器动量精度** —— `Fp8AdamW` 的 m/v 是 bf16，`AdamW` 是 fp32
3. **初始权重不同** —— 同一 seed 下 126 个参数张量里 **75 个逐位不同**。
   `te.Linear` 默认 `normal(0, 0.023)` 而 `nn.Linear` 是 kaiming_uniform，
   分布本身就不一样（`blocks.1.mlp.up` 平均绝对值 0.0312 vs 0.0183）；
   两者消耗的 RNG 流长度也不同，连不含 TE 的卷积和位置嵌入都跟着错位。

第 3 条最隐蔽：`ab_experiment.sh` 把超参、种子、卡数、线程数全锁死了，
所有**显式**的控制变量都对得上，但初始化是在两个不同的库里各自完成的。
**锁住种子不等于锁住初值。**

三者现在都已消除（统一 master、统一 m/v、`make_linear` 用 fp32 参考层对齐初始化），
外加 recipe 从 E4M3 换成 HYBRID —— 新旧不是同一条实验，**这个数需要重跑**。
`test_both_legs_start_from_identical_weights` 从此守着第 3 条。

## 后续优先级

1. **弄清 20% 处见顶的成因**。见上面那条。这是现在最该花时间的地方，
   其余优化都要等它有结论才谈得上收益。
2. **在新脚手架上重跑 FP8 / BF16 的 A/B**。旧结论纠缠了三个变量（见上），
   现在两条腿只差 GEMM 精度，是第一次真正的单变量对照。
3. **CUDA Graph**。批的形状已经固定（`fixed_batch`），这是顺理成章的下一步，
   能再削掉一截内核下发开销。
4. **异步自博弈**。把自博弈与训练拆成独立进程，用共享内存传对局。
   顺带解决 FP8 的多卡问题（每卡一个进程，各自持有独立的 TE 状态）。
5. **加宽模型**。当前 14.2M 参数在 Blackwell 上偏瘦。等 Elo 曲线走平之后，
   `dim=384/512` 是自然的下一档 —— 也是 FP8 唯一可能真正回本的方向。
6. **单局面搜索批量化**（virtual loss），直接改善试玩体验。
7. **开局多样性**。目前靠 Gumbel 噪声与 `temperature_plies`。
   如果发现自博弈棋局趋同，可以加开局随机化或对局去重。

## 值得记住的几条经验

- **每一次「看起来是 X 慢」都要先量**。自博弈最初以为 GPU 不够快
  （GPU 占墙钟 81%），实际是核函数启动受限；修完之后瓶颈立刻跳到单线程的 C++ 侧。
  三次瓶颈转移，没有一次是靠猜对的。
- **数值 bug 不会崩，只会让效果变差**。量化前多过一道 bf16 让随机舍入完全失效，
  但 loss 照样在降。这类问题只能靠「小更新能不能存活」这种针对性测试抓出来。
  （随机舍入已随 FP8 主权重一并移除，但这条性质换了载体继续守着：
  没有 fp32 master 时，退火终点学习率下的更新只走应走位移的 **0.1%**。）
- **锁住种子不等于锁住初值**。见上面那条 A/B 的第 3 点：两条腿的显式超参逐字相同、
  种子相同，初始权重却有 60% 的张量不一样，因为初始化发生在两个不同的库里。
- **探针不能挂在告警上**。靠捕获 UserWarning 判断 FP8 是否降级，
  在告警的触发条件消失之后会静默退化成恒真 —— 比没有探针更糟，
  因为它还在持续输出「一切正常」。
- **多线程正确性要逐位对齐单线程**。竞态在这里表现为「训练效果变差」而不是崩溃。
- **报错点常常离根因很远**。FP8 多卡的根因是设备绑定，
  但最先炸的是注意力里 cuDNN 的 `mha_graph.execute`。
- **数据格式的选择要看真实分布**。策略目标存 top-32 看着够用，
  实测 `rest_prob ≈ 0.90` —— 归一化就等于把训练目标改成了另一回事。
- **对照实验要先自检再看结论**。换一种对齐方式（按 step / 按累计对局数）
  如果结论翻转，那它测的就不是你以为的那个变量。
- **别让「哪个是 A」靠位置约定传递**。`ab_experiment.sh` 按 `(B, A)` 的顺序
  调 `compare_nets.py`，自己却 echo 一行「A=ab-bf16 为 BF16」，
  而 `compare_nets.py` 把第一个位置参数叫 A —— 两行相反的说法出现在同一屏输出里。
  「得分率 0.600」于是可以被读成完全相反的结论，**而这正是整个对照实验
  唯一要产出的那一个结论**。没有任何报错，两边单独看都自洽。
  修法不是把顺序对齐（那还是靠约定），是让工具**把实验名印在每一行上**，
  再加一行「→ 领先方：xxx」。凡是「结论正负号取决于参数顺序」的地方都该这么办。
