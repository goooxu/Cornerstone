# 网络与自博弈训练

## CornerNet

自研结构，围绕两件事设计。

### 一、FP8 GEMM 是主体

主干由 **PolyBlock** 堆叠：

```
x = x + DepthwiseConv5x5(RMSNorm(x))        空间混合，FLOPs 占比 <2%
x = x + Attention(RMSNorm(x))               每 4 个 block 一次，196 个格 token 全局注意力
x = x + SwiGLU(RMSNorm(x))                  通道混合，D -> 4D -> D，FLOPs 主体
```

深度可分离卷积提供局部归纳偏置但几乎不耗算力；真正吃算力的是 SwiGLU 里那两个大 GEMM
和注意力的四个投影 —— 这些全部经由 `make_linear()` 创建，M4 里把这一个函数换掉
就切到 FP8，不动主干代码。

输出头：

- **策略头** `D -> 91`，每个格给出 91 个朝向的 logit，转置展平成 `ori*196 + cell`，
  正好对上引擎的动作编码
- **价值头** WDL 三分类 softmax。本项目和局是真实结果（随机对局下 4.5%），
  tanh 标量没法区分「这是和棋局面」和「胜负各半的混沌局面」
- **辅助头** 终局占格数差回归。信号比稀疏的三分类密集得多，早期收敛主要靠它

`D=256, blocks=16` 时 **14.2M 参数**。

### 二、零拷贝的双视图

张量全程保持 `(B, 196, D)` 连续布局。关键性质：**一个连续的 `(B,196,D)` 张量
在物理上就是 channels_last 的 `(B,D,14,14)`**，所以

```python
xc = x.view(B, 14, 14, D).permute(0, 3, 1, 2)     # 纯视图，data_ptr 不变
y  = conv(xc)                                      # cuDNN channels_last 快路径
back = y.permute(0, 2, 3, 1).reshape(B, 196, D)    # 纯视图
```

两边都不产生拷贝。不注意这一点的话，每个 block 要来回两次 200 MB 级别的转置 ——
16 个 block 就是 6 GB 的无谓搬运。有单测（`test_token_view_is_really_zero_copy`）
拿 `data_ptr()` 守着这条性质。

### 策略头零初始化

`policy.weight` 和 `bias` 都初始化为 0，于是训练第一步的先验就是**合法着法上的均匀分布**。
不这么做的话，MCTS 一开始就被一个随机的强先验带偏，自博弈数据的质量会差很多。

## Gumbel AlphaZero

用 Gumbel-AZ 而不是原版 AlphaZero，是被 Blokus 的形状逼出来的：动作空间 17836，
单步合法着法常有几百个（开局就有 414 个）。原版靠 PUCT + Dirichlet 噪声探索，
在这种宽度下要很大的模拟数才能让根节点的访问分布有统计意义。
Gumbel-AZ 在根节点用 Gumbel top-k 采样出 m 个候选、再用 sequential halving 分配预算，
**低模拟数下的策略改进有理论保证**。

实现要点：

- 根节点：`g_a + log π(a)` 取 top-m 作为候选；每轮给每个候选 `n/(R·|S|)` 次访问，
  轮末按 `g_a + log π(a) + σ(q_a)` 砍掉一半
- 内部节点：`argmax_a [ improved_π(a) − N(a)/(1+ΣN) ]`，
  `improved_π = softmax(log π + σ(completed_q))`，未访问动作的 q 用 `v_mix` 补全
- **回传符号不能按深度奇偶定**。Blokus 有停手规则，同一方可能连走两手，
  所以每个节点存自己的行棋方，回传时按实际行棋方定符号

### 批量方式：多局并行，单局单叶子

同时开很多局，**每局在任意时刻只有一个待评估的叶子**。批量大小来自局数，
不是单局内的并行叶子数。这样：

- 不需要 virtual loss（单局内不会有并发的搜索路径）
- 不需要多线程回调 Python（Python 驱动循环，C++ 只做树的工作）

驱动循环：

```python
while True:
    n = engine.prepare(planes, scalars)   # C++，已释放 GIL
    if n: engine.feed(*model(planes[:n], scalars[:n]))
    else: games += engine.advance()
```

## 训练目标的存法：稀疏 top-K + 尾部质量

策略目标**不做归一化**，存 top-32 的原始概率外加一个 `rest_prob`。

这不是省事，是必须的。实测训练早期 `rest_prob ≈ 0.90` —— 先验接近均匀、
合法着法几百个时，top-32 只装了约 10% 的概率质量。
若把 top-32 归一化当目标，等于在教网络集中到一组**本质上任意**的着法上
（未访问动作之间只按先验排序，而先验此时是均匀的）。

训练时把 `rest_prob` 均摊到其余合法着法上：

```
loss = -( Σ_top p_a·log q_a  +  rest_prob · mean_{a∈legal\top} log q_a )
```

一个隐蔽的坑：补位槽（`n_top` 之后的槽）概率是 0，但**动作编号必须仍指向合法着法**。
否则 gather 会取到 `-inf` 的 log 概率，再乘 0 就是 NaN。代码里用第 0 个
（一定合法）的动作填充补位槽，并且在损失里用 `where` 而不是乘法屏蔽。

## Replay buffer：只存着法序列

一局约 27 手，每手 32 个 `(int32 动作, fp32 概率)` ≈ 260 B，加着法本身约 **7 KB/局**。
稠密策略目标是每手 17836 个 float = 71 KB/**手** —— 差三个数量级。
工作目录只剩百来 GB，这是唯一可行的存法。

局面特征在取批时由 C++ `build_batch` 从着法序列**重建**：每局只回放一次、
一次性吐出该局被抽中的全部 ply（所以要求 ply 递增，Python 侧先按 `(局, 手)` 排序）。
CPU 有 144 核，用算力换存储是划算的。

对称增广也在 `build_batch` 里做完：几何变换直接作用在特征平面和合法掩码上，
稀疏策略目标的动作编号重映射留给 Python（一次 numpy 花式索引）。

**正确性由单测守着**：`test_build_batch_matches_plain_replay` 逐字节比对
`build_batch` 的输出与「用 Board 老老实实回放一遍」的结果。这条不测的话，
训练数据错了也很难从 loss 曲线上看出来。

## 评测记录不能进 replay buffer

评测模式下网络方用搜索、对手用规则基线，对局记录里**只有网络方走的手**
（随机开局和对手的着法都没记）。从空棋盘回放这样的序列会得到非法着法序列。

记录里带一个 `selfplay` 标记，`ReplayBuffer.add_records` 直接拒绝非自博弈记录。
不加这道拦截的话，要等到 `build_batch` 里 `Board::play` 抛异常才会暴露，那时已经很难查。

## 端到端自检

`tools/train.py --smoke` 用一套小配置（0.8M 参数、128 并行局、32 次模拟）
跑通「自博弈 → replay → 训练 → 落盘」的完整环路，几分钟出结果。
用途是改完代码验证管线没断，不是拿来出棋力结论的。

判断标准很简单：价值损失要从 `ln3 ≈ 1.099`（三分类的均匀分布）明显往下走，
策略熵要单调下降。

> 原先还有一条「对 `greedy-area` 的得分率要能越过 0.5」。训练期的周期性评测
> 已经移除（规则基线量不了这个网络，见 [08](08-已知问题与后续.md)），
> 这条判据随之失效 —— 要看棋力得事后跑 `tools/net_arena.py`。

## 吞吐

这个模型很瘦（D=256），一开始自博弈是**核函数启动受限**的：单次前向约 10 ms
且与批大小几乎无关。C++ 侧从来不是瓶颈（128 线程 1030 万次着法生成/s）。

优化过程与最终数字见 [07-性能调优.md](07-性能调优.md)。
