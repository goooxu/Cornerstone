# Cornerstone：Blokus Duo 自博弈模型（BF16）训练报告

## 摘要

从零规则出发、不使用任何人类棋谱，训练出一个 14.2M 参数的 Blokus Duo 自博弈模型。

| | |
|---|---|
| 网络 | CornerNet，自研结构，14.2M 参数（D=256，16 个 block） |
| 训练方法 | Gumbel AlphaZero 自博弈，每手 64 次模拟 |
| 规模 | **200,230 步 / 501 轮 / 1,074,512 局自博弈 / 2.05 亿个训练局面** |
| 墙钟 | **37.1 小时**（4×GB200） |
| 棋力 | **纯策略**（无搜索）下最强 **1622 Elo**（步 90,230，锚定 `random = 0`），比最强规则基线 `greedy-mobility` 高 **+745**；见 [§6](#6-棋力评测) |

四条主要结论，都不是「训练很顺利」这种话：

1. **80% 的棋力增长发生在前 4 万步（训练量的 20%）**，而**最强的一档在第 9 万步**。
   把 20 档 checkpoint 全对全打完（300 对 / 12 万局）之后，最后那一档
   `step00200230.pt` 只排第 12 —— 比峰值低 **35.9 ± 7.9** 分，2000 次自举里
   **没有一次**让它反超。也就是说后 55% 的训练不但没有提升棋力，还略微退了一点。
2. **loss 不是棋力代理，而且这次能给出机制。** 总损失在第 172,230 步触底
   （1.3039），随后回升 11% 到 1.4474。回升全在策略项，而 `policy_entropy`
   与 `policy` 的差值中位数只有 4.7e-4，比损失值本身（约 1.4）小三到四个数量级
   —— 说明策略损失几乎等于**目标本身的熵**。
   网络早就把自己的搜索分布拟合到位了，loss 变化反映的是**目标变了**，不是学坏了。
3. **自博弈分布塌缩了。** 先手胜率从 0.55 一路涨到 **0.992**，和局率掉到 0.003。
   后 40% 的训练几乎没有「负局」信号，价值头在学一个近乎常数 ——
   0.034 的 value loss 和 0.993 的准确率好看，但没有信息量。
4. **评测吃掉的墙钟比自博弈加训练还多**：19.9 小时 vs 16.4 小时。根因是个真 bug
   （评测路径单线程），已修；详见 [§7.3](#73-工程教训)。

> **口径**：§6 的棋力一律是**纯策略**（每手只做一次前向，落 `argmax(prior)`，
> 不做任何搜索）。要量的是模型本身 —— 搜索会把弱网络的短板补上。
> 加上搜索会显著更强，但那是另一个口径，两者不能拼接。

## 1. 任务与约束

### 1.1 规则

Blokus Duo，两人对弈：

- 棋盘 14×14 = 196 格
- 每方 21 枚多联骨牌（1~5 格），合计 **89 格**
- 起始格 (4,4) 与 (9,9)，首手必须盖住自己的起始格
- 之后每一手必须与己方已有棋子**恰好角接触**，且**不得边接触**
- 无处可下即停手；双方都停手则终局
- **占格多者胜，相同为和局**

### 1.2 四条硬约束

| 约束 | 推出的结论 |
|---|---|
| 不使用棋谱 | 只能自博弈强化学习。连**评测基线**也必须由规则构造 |
| 不复用开源 Blokus AI 结构 | 网络结构自研 |
| 低精度混合训练 | 结构要把算力集中在大 GEMM 上，低精度的收益才吃得到 |
| 压满 CPU 与 GPU | CPU 跑搜索与着法生成，GPU 跑批量推理与训练 |

### 1.3 动作空间

21 枚棋子按「4 旋转 × 2 镜像」展开去重后恰好 **91 个不同朝向**（生成时断言这个数）。
动作编码为 `朝向 × 196 + 包围盒左上角格号`，于是动作空间是

```
91 × 196 = 17,836
```

这个数字直接决定了后面几个设计：策略头的形状、稀疏策略目标的存法、
以及为什么要用 Gumbel-AZ 而不是原版 PUCT。

## 2. 模型结构：CornerNet

### 2.1 为什么不是卷积 ResNet

常见的开源 Blokus/围棋类实现是卷积 ResNet。本项目不能复用，也不想复用：
结构要围绕「**FLOPs 尽量集中在大 GEMM 上**」来设计 ——
低精度矩阵乘的收益只在 GEMM 上，卷积吃不到。

最终的形态是「把 196 个格子当成 196 个 token」的 Transformer 变体，
局部性由一层深度可分离卷积提供（几乎不耗算力），算力主体是 SwiGLU 的两个大 GEMM。

### 2.2 输入

| | 形状 | 内容 |
|---|---|---|
| 平面 | 9 × 14 × 14 | 己方占格、对方占格、己方可落区、己方角点前沿、对方可落区、对方角点前沿、己方起始格、对方起始格、全 1 |
| 标量 | 44 | 21 位己方剩余棋子 + 21 位对方剩余 + 己方占格/89 + 对方占格/89 |

两点值得说：

- **一切都是「行棋方视角」**，不是「先手视角」。这样座位交换类的对称增广才成立。
- **标量里放的是占格数，不是手数 ply。** 这不是随手选的：`rot180` 与反对角变换
  会把己方起始格映射到另一个座位的起始格，而 ply 的奇偶性和座位绑定 ——
  用 ply 会让这两个增广产生分布外样本。占格数是座位无关的。

### 2.3 主干

```
stem:  Conv2d(9 → D, 3×3)  →  展平成 (B, 196, D)
       + 学习式位置嵌入 (1, 196, D)
       + 标量 MLP(44 → D → D) 广播加到每个 token

PolyBlock × 16（pre-norm 残差，全部 RMSNorm）：
       x = x + DepthwiseConv5×5(RMSNorm(x))      空间混合，FLOPs 占比 <2%
       x = x + Attention(RMSNorm(x))             每 4 个 block 一次，196 token 全局注意力
       x = x + SwiGLU(RMSNorm(x))                通道混合，D → 4D → D，算力主体

norm_out: RMSNorm(D)
```

`D=256, blocks=16, attn_every=4, heads=8, dw_kernel=5`。注意力落在第 4/8/12/16 个
block（共 4 层），无 mask、无 RoPE —— 196 个格子之间是全连接的双向注意力，
位置信息完全由那个学习式嵌入提供。没有 dropout、没有 layer-scale、没有 stochastic depth。

**零拷贝的双视图。** 张量全程保持 `(B, 196, D)` 连续布局，而一个连续的
`(B, 196, D)` 在物理上就是 channels_last 的 `(B, D, 14, 14)`，所以

```python
xc = x.view(B, 14, 14, D).permute(0, 3, 1, 2)     # 纯视图，data_ptr 不变
y  = conv(xc)                                      # cuDNN channels_last 快路径
back = y.permute(0, 2, 3, 1).reshape(B, 196, D)    # 纯视图
```

两边都不产生拷贝。不注意这点的话，每个 block 要来回两次 200MB 级的转置，
16 个 block 就是 6GB 的无谓搬运。有单测拿 `data_ptr()` 守着这条性质。

### 2.4 三个输出头

| 头 | 结构 | 语义 |
|---|---|---|
| 策略 | `Linear(D → 91)` 逐 token | 转置展平成 `朝向×196 + 格号`，直接对上引擎的动作编码 |
| 价值 | `Linear(2D → D) → SiLU → Linear(D → 3)` | **WDL 三分类**，行棋方视角 |
| 辅助 | `Linear(2D → D) → SiLU → Linear(D → 1)` | 终局占格差 / 89 的回归 |

后两个头的池化是 `concat(mean_pool, max_pool)`，所以输入是 2D。

**价值头为什么是三分类而不是 tanh 标量**：本项目和局是真实且不罕见的结果
（随机对局下 4.5%），tanh 标量没法区分「这是和棋局面」和「胜负各半的混沌局面」。
MCTS 回传时用 `P(胜) − P(负)`。

**策略头零初始化**：`policy.weight` 和 `bias` 都初始化为 0，于是训练第一步的先验
就是**合法着法上的均匀分布**。不这么做，MCTS 一开始就被一个随机的强先验带偏，
自博弈数据质量会差很多。

**合法性 mask 不在模型里。** 网络输出未经掩码的 17836 维 logits，
由三个调用方各自施加：训练走 `masked_log_softmax`，自博弈交给 C++
（在合法子集上做 softmax），推理用 `mask_logits()` 填 `-inf`。

### 2.5 参数量

`D=256, blocks=16` 时 **14,183,007 ≈ 14.2M**。最后一列是**前向的计算精度**——
参数本身**一律以 fp32 存储**，低精度只发生在前向计算里（`torch.autocast` bf16）：

| 部件 | 参数量 | 占比 | 前向计算精度 |
|---|---:|---:|---|
| SwiGLU（16 层 × 12D²） | 12,582,912 | 88.72% | bf16 GEMM |
| 注意力投影（4 层 × 4D²） | 1,048,576 | 7.39% | bf16 GEMM |
| 价值头 | 132,099 | 0.93% | bf16 GEMM |
| 辅助头 | 131,585 | 0.93% | bf16 GEMM |
| 深度卷积（16 层 × 5×5） | 106,496 | 0.75% | bf16 卷积 |
| 标量 MLP | 77,312 | 0.55% | bf16 GEMM |
| 位置嵌入 | 50,176 | 0.35% | 只做加法 |
| 策略头 | 23,387 | 0.16% | bf16 GEMM |
| stem 卷积 | 20,992 | 0.15% | bf16 卷积 |
| 各 RMSNorm | 9,472 | 0.07% | **fp32** |
| **合计** | **14,183,007** | **100.00%** | |

**96.1% 的参数落在大 GEMM 上**（SwiGLU + 注意力投影）—— 这正是上面那条设计取向的
直接结果。

关于精度，有三件事容易混：

1. **存储与计算是两回事。** 参数、AdamW 的一阶/二阶动量全是 fp32；bf16 只出现在
   前向。所以权重占 54.1 MiB，而一份 checkpoint 是 162.5 MiB —— 正好三倍。
2. **只有 RMSNorm 的增益留在 fp32**，共 9,472 个参数（**0.07%**）。
   这不是本项目的选择，是 `torch.autocast` 的既定策略：归一化在 bf16 下算方差会掉精度。
   其余 99.93% 的参数都以 bf16 参与计算。
3. **损失在 fp32 里算**（`train.py` 里显式 `.float()`）：策略是 17836 类的
   log_softmax，bf16 的尾数不够用。

## 3. 训练方法

### 3.1 Gumbel AlphaZero

用 Gumbel-AZ 而不是原版 AlphaZero，是被 Blokus 的形状逼出来的：动作空间 17836，
单步合法着法常有几百个（**开局就有 414 个**）。原版靠 PUCT + Dirichlet 噪声探索，
在这种宽度下要很大的模拟数才能让根节点的访问分布有统计意义。
Gumbel-AZ 在根节点用 Gumbel top-k 采样出 m 个候选、再用 sequential halving 分配预算，
**低模拟数下的策略改进有理论保证**。

实现要点：

- 根节点：`g_a + log π(a)` 取 top-m（`max_considered=16`）作为候选；
  轮末按 `g_a + log π(a) + σ(q_a)` 砍掉一半
- 内部节点：`argmax_a [ improved_π(a) − N(a)/(1+ΣN) ]`，
  `improved_π = softmax(log π + σ(completed_q))`，未访问动作的 q 用 `v_mix` 补全
- **回传符号不能按深度奇偶定**。Blokus 有停手规则，同一方可能连走两手，
  所以每个节点存自己的行棋方，回传时按实际行棋方定符号

### 3.2 自博弈：多局并行，单局单叶子

同时开很多局，**每局在任意时刻只有一个待评估的叶子**。批量大小来自局数，
不是单局内的并行叶子数。这样：

- 不需要 virtual loss（单局内不会有并发的搜索路径）
- 不需要多线程回调 Python（Python 驱动循环，C++ 只做树的工作）

驱动循环就三行：

```python
while True:
    n = engine.prepare(planes, scalars)   # C++，已释放 GIL
    if n: engine.feed(*model(planes[:n], scalars[:n]))
    else: games += engine.advance()
```

四卡数据并行：每卡一个模型副本 + 一个独立引擎，各 2048 局、32 个引擎线程，
用 Python 线程驱动（C++ 引擎和 CUDA 下发都释放 GIL，所以线程能真并行）。
每轮自博弈开始前同步一次权重 —— 也就是说自博弈用的是**上一轮**的权重。

### 3.3 训练目标的存法：稀疏 top-K + 尾部质量

策略目标**不做归一化**，存 top-32 的原始概率外加一个 `rest_prob`。

这不是省事，是必须的。实测训练早期 `rest_prob ≈ 0.90` —— 先验接近均匀、
合法着法几百个时，top-32 只装了约 10% 的概率质量。若把 top-32 归一化当目标，
等于在教网络集中到一组**本质上任意**的着法上。

训练时把 `rest_prob` 均摊到其余合法着法上：

```
loss_policy = -( Σ_top p_a·log q_a  +  rest_prob · mean_{a∈legal\top} log q_a )
```

一个隐蔽的坑：补位槽的概率是 0，但**动作编号必须仍指向合法着法**，
否则 gather 会取到 `-inf`，再乘 0 就是 NaN。代码里用第 0 个（一定合法）的动作填充。

### 3.4 Replay buffer：只存着法序列

一局约 30 手，每手 32 个 `(int32 动作, fp32 概率)` ≈ 260B，加着法本身约 **7 KB/局**。
稠密策略目标是每手 17836 个 float = 71 KB/**手** —— 差三个数量级。

局面特征在取批时由 C++ `build_batch` 从着法序列**重建**。CPU 有 144 核，
用算力换存储是划算的。容量 3,000,000 个局面，第 23,030 步起一直是满的。

### 3.5 对称增广：克莱因四元群

```
恒等        (r,c) → (r,c)
转置        (r,c) → (c,r)            两个起始格都不动
旋转 180°   (r,c) → (13-r,13-c)      两个起始格互换
反对角      (r,c) → (13-c,13-r)      两个起始格互换
```

**不是完整的 D4（8 个元素）** —— 起始格集合 {(4,4),(9,9)} 只被这四个变换保持。
旋转 180° 和反对角会交换座位，这之所以合法，正是因为特征是行棋方视角、
且标量用的是占格数而非 ply（见 §2.2）。

增广在取批时做，每次抽样独立随机选一个变换，所以同一个局面在不同 epoch 会
看到不同的对称形态。

### 3.6 损失与优化

```
loss = policy + 1.0 × value + 0.25 × score(辅助头)
```

- 价值：普通交叉熵，三分类，无 label smoothing
- 辅助：`smooth_l1(beta=0.1)`，目标是终局占格差 / 89

优化器 AdamW，`betas=(0.9, 0.95)`，`eps=1e-8`，`weight_decay=0.01`
**只加在矩阵和卷积核上**（norm、bias、位置嵌入都不加）。
`grad_clip=1.0`。前向在 bf16 autocast 下，**但损失在 fp32 里算** ——
策略是 17836 类的 log_softmax，bf16 精度不够。

学习率：线性 warmup 500 步到 `2e-3`，然后余弦退火到 `2e-4`（`0.1×`）。

**按数据量限流**（`steps_for_iteration()`）：buffer 还小的时候不许跑满 400 步，
上限是 `len(buffer) × 4 / batch_size`。不加这条的话，等于在少量局面上反复训练几十遍 ——
loss 会明显变好看，但那是坏了。

## 4. 训练过程

### 4.1 规模

| | |
|---|---|
| 步数 / 轮次 | 200,230 / 501 |
| 自博弈对局 | 1,074,512 |
| 训练局面 | 200,230 × 1024 ≈ 2.05 亿 |
| 墙钟 | 37.1 小时 |
| 每训练步产生的对局 | 5.37 |

### 4.2 一轮里发生什么

**一轮 = 一次自博弈 + 400 个训练步**，两者严格交替、不重叠。步数和轮次的关系是

```
200,230 步 = 230 + 500 × 400
              ↑          ↑
         第 1 轮      其余 500 轮，每轮都是整 400 步
```

第 1 轮只跑了 230 步，是被 `steps_for_iteration()` 按数据量限流的（见 §3.6）——
当时 replay 里只有 58,885 个局面，上限 `58885 × 4 / 1024 = 230`。
**这条限流全程只生效了这一次**：第 2 轮 replay 就到 12 万，上限 472 > 400，此后一直够用。

一轮内部按时间顺序：

| | 阶段 | 中位耗时 | 说明 |
|---|---|---:|---|
| ① | 同步权重 | — | 把上一轮训好的权重推给四张卡的自博弈副本 |
| ② | 自博弈 | **68.7s** | 目标 2048 局，实测 2,057–2,653 局（全程平均 2,145） |
| ③ | 入库 | — | 着法序列写进 replay buffer；①③ 合计约 2.2s |
| ④ | 训练 | **48.1s** | 从 buffer 采样，跑 400 步 |
| ⑤ | 评测 | **1387.8s** | **每 10 轮才有一次**，对固定的评测基线打 200 局 |

所以普通轮 **119s**，评测轮 **1507s** —— 差 12.7 倍。

![一轮的时间线](图表/一轮的时间线.png)

**自博弈用的是上一轮的权重**：步骤 ④ 训出来的新权重要等下一轮的 ① 才生效。
局数为什么不是整 2048 —— 驱动循环按整批 `advance()` 追加结果，跨过目标那一刻会把
整批都收下，所以总是略多。

下面那条横杠是全程 37.1 小时的去向。**评测一项就吃掉 19.9 小时（54%）**，
比自博弈加训练（16.4 小时）还多。这不是「测得太勤」——
50 次评测本身不算多，是每一次都跑了单线程，见 [§7.3](#73-工程教训)。

### 4.3 损失曲线

![损失曲线](图表/损失曲线.png)

**总损失在第 172,230 步触底（1.3039），之后回升 11% 到 1.4474。**
把这 +0.1436 拆到三项上（`loss = policy + 1.0×value + 0.25×aux`）：

| 分项 | 172,230 → 200,230 | 对总损失的贡献 |
|---|---|---:|
| 策略 | 1.2083 → 1.4112 | **+0.2029** |
| 价值 | 0.0937 → 0.0338 | −0.0599 |
| 辅助（终局占格差回归） | 0.00721 → 0.00972 | +0.0006 |

三块面板分别对应这段的三个事实（图内标注为英文 —— 运行环境里没有中文字体）：

- **下**：同一段时间里价值损失还在降、WDL 准确率还在升，**和总损失方向相反**。

这不是发散。真正的解释见 [§7.1](#71-loss-与棋力脱钩)。

## 5. 评测方法

### 5.1 为什么要自建规则阶梯

不许用棋谱，就没有现成的测试集，也没有外部的 Elo 参照系。所以基线必须由规则构造：

| 名字 | 做法 |
|---|---|
| `random` | 均匀随机合法着法。Elo 零点 |
| `greedy-area` | 只看棋子格数 |
| `corner-min` | 只最小化对方角点前沿 |
| `greedy-mobility` | `4·格数 + 0.5·己方角点前沿 − 20·对方角点前沿`（权重扫出来的） |
| `flat-mcts-1k` | 1024 次 rollout 预算平摊到每个候选着法，取平均结果最好的 |

四条不能省的设计：

1. **同分随机打散** —— 否则两个贪心智能体跑 400 局等于跑了 1 局。
2. **开局随机 2 手** —— 双方各 1 手，给对局引入多样性。2 手就够：首手有
   **414 种**合法着法，随机采样 2 万个 2 手开局得到 **18,865 个互不相同**的开局，
   一场 400 局里只用到 200 个开局，撞车概率可忽略。
3. **先后手逐局交换** —— 先手优势约 4 个百分点。
4. **开局成对**：第 2k 与第 2k+1 局用**同一个随机开局**，只是执先方相反。

第 4 条单独说一下。随机开局不可能对双方绝对中立，某个开局可能天然利于先手或
后手 —— 不配对的话，一个碰巧利于某方的开局只会被那一方碰上，公平性只在期望
意义上成立。配对之后，每个开局双方各走一次，这一项影响被逐对消掉。

实现上是让相邻两局共用同一个 rng 种子（规则路径按 `i/2` 派生；评测路径在每个
槽位里存一份开局 rng 快照，第二遍恢复它）。判据很硬：**同一个智能体自我对局，
得分率必须精确等于 0.5** —— 一对里两局逐手完全一样、只是执先方相反，
必然一胜一负抵消。实测 `random / greedy-area / corner-min / greedy-mobility /
flat-mcts-1k` 五个智能体全是 0.5000，胜负数也完全对称（如 191 胜 / 18 和 / 191 负）。
单测盯着这条。

### 5.2 训练期间那条评测线的两个问题

训练时每 10 轮对一个固定的 flat-MCTS 基线（每手 4096 次 rollout）打 200 局，
网络侧用 128 次模拟。这条线有两个毛病，报告里不能直接引用：

**一、第 5.2 万步就饱和了**，也就是整个训练的 26% 处。此后 38 次评测的平均
得分率是 0.9865，最低 0.9650 —— 全部落在 200 局的二项噪声范围内。
基线分辨不出任何进一步的提升。

| 阈值 | 首次达到 | 达到次数 |
|---|---|---|
| ≥ 0.90 | 第 39,830 步 | 41 / 50 |
| ≥ 0.98 | **第 51,830 步** | 32 / 50 |
| = 1.000 | 第 111,830 步 | 6 / 50 |

**二、6 个满分点换算出的 Elo 是钳位假数。** 200:0:0 时
`elo_from_score_rate` 把得分率钳到 `1 − 1e-9`，于是输出
`−400·log10(1e-9) = +3600`，绝对 Elo 变成 4591.6。这 6 个点必须从任何曲线里剔除。
最后一个**非饱和**的测量是第 123,830 步的 +1040（199胜1和0负）。

### 5.3 棋力怎么测

把 **20 档 checkpoint 和 5 个规则基线放进同一场单循环**，全对全 300 对、
每对 400 局，一次 Bradley-Terry 联合拟合（`tools/net_arena.py`），锚定 `random = 0`。

**网络一律不用搜索**（`--simulations 0`，纯策略：一次前向，落 `argmax(prior)`）。
理由是要量的是**模型本身**：搜索会把弱网络的短板补上，测出来的是「网络 + 搜索」
的合力；而对局多样性已经由随机开局提供，不需要再靠搜索制造差异。
规则基线不变 —— `flat-mcts-1k` 的定义就是 rollout。

> `simulations=0` 之所以就是纯策略：一个子节点都没被访问过，于是所有 `n[i]=0`、
> q 一律等于 `v_mix`，`improved_policy = log(prior) + 常数`，argmax 就落在
> `argmax(prior)` 上。实现上要把根节点的评估提到模拟预算循环外面（本次引擎改动），
> 否则驱动循环会空转。验证方式是喂固定 logits，落子必须逐手等于
> `argmax(合法 logits)` —— 实测 26 手全中。

误差用**参数自举**（400 次重采样后重新拟合），且**按「对」而不是按「局」重采样**——
开局是成对的，同一对里的两局强相关（纯策略下更是由开局唯一决定），
按 400 局独立二项试验算会高估精度。配对得分取值于 {0, 0.5, 1}，方差恒 ≤ p(1−p)，
所以按对重采样是保守上界。不用 `elo_stderr`：它依赖各人碰到的对手组合，跨行不可比。

工具是 `tools/net_arena.py`（本次新增）。落地前先验证了**胜负方向没写反** ——
这是唯一会让整份报告结论翻转的错误，而这个项目真犯过一次（见 `docs/08`）：
`evaluate_vs_baseline` 报的是**网络方**的胜负，网络坐第二个位置时必须翻过来。
三道检查：8 项单测盯住三种分派路径的方向与互补性；只放规则基线单独跑一遍，
Elo 次序必须复现 `docs/03`（已复现）；运行时硬断言两条**与参赛者无关**的不变量 ——
「训练了 20 万步的网络必须强于最早那一档」「最强的规则智能体必须碾压 `random`」，
不满足就直接崩，不输出看着合理的反表。

（断言不能钉死在某个具体基线上 —— 参赛者一换，那段就会整体跳过，等于没有自检。）

> **可比性提醒**：Elo 是相对的。这张表把规则阶梯和网络放进**同一次拟合**，
> 各档绝对值会和 `docs/03` 里那张表有出入（实测同一批对局数据，
> 仅仅改变参与拟合的对手集合，规则智能体的 Elo 就能动 30 分左右）。
> **同一张表内部可比，跨表只看次序。**

### 6.5 测量的边界

- **纯策略口径**。网络不带搜索，量的是模型本身。加上搜索会显著更强 ——
  §5.2 里训练期间那条评测线（128 次模拟）对它的评测基线打到 0.98 以上，
  而纯策略下网络虽然仍远强于全部规则基线，但两者不是一个口径，不能拼接。
- **绝对刻度靠一条弱边**。见 §6.2。规则阶梯只留了 `flat-mcts-1k`，
  而它对所有 20 档网络都是 0:400 —— 想把绝对刻度钉死，需要更强的规则基线，
  或者干脆承认「网络这一块的内部排序」才是这次能给出的可靠结论。
- **Bradley-Terry 假设可传递**，而近实力的档位之间存在不可传递性
  （90,230 输给 120,230 却总分更高就是一例）。单一 Elo 数字是近似。
- **单次运行，n=1**，没有换种子重跑。

## 7. 观察与结论

### 7.1 loss 与棋力脱钩

策略目标是**网络自己的 MCTS 搜索结果**。网络变强 → 搜索出的目标更尖锐 →
可达到的 loss 随之改变。所以 loss 高低不直接对应棋力，这一点在实验协议里
早就写死了（`scripts/ab_experiment.sh` 的注释）。

这次能把机制说得更实：**`policy` 与 `policy_entropy` 的差值中位数只有 4.7e-4**，
第 2 万步之后始终不超过 2.2e-3，第 10 万步之后中位数降到 8.0e-5，
最终是 3.1e-4（1.4112 vs 1.4109）。相对约 1.4 的损失值，这是三到四个数量级的差距。
（最大值 1.1e-2 出现在第 1,030 步，属于训练刚起步、网络还没跟上目标的阶段。）

也就是说，策略损失几乎完全等于**目标分布本身的熵** ——
网络对自己搜索结果的预测误差已经小到可以忽略。

于是第 172,230 步之后 loss 回升 11%，反映的不是「学坏了」，而是
**搜索目标的熵变大了**。同期价值损失降到 0.0338、WDL 准确率升到 0.9928，
两者方向相反 —— 单看总 loss 会得出完全错误的结论。

### 7.2 自博弈分布塌缩

先手胜率 **0.992**、和局率 **0.003**，而平均手数一直是 30 手。
这意味着后 40% 的训练里，自博弈几乎只产生「先手赢」这一种结局。

后果是价值头在学一个近乎常数。0.0338 的 value loss 和 0.9928 的 WDL 准确率
**看起来是全篇最漂亮的数字，实际上信息量最低** —— 预测「先手赢」就能拿到 99%。

可能的原因（未逐一验证，属于下一步的工作）：

- 每手只有 64 次模拟，对 17836 的动作空间偏低
- `temperature_plies=12` 相对 30 手的对局偏短，后 60% 的着法全是 argmax
- 配置里没有 Dirichlet 噪声这类显式的探索项，探索完全靠 Gumbel 噪声

**这条和 §6 的平台期大概率是同一件事的两面。** 时间上对得很齐：
先手胜率在第 6 万步左右越过 0.90，而棋力也正是在第 4–6 万步之后开始变平、
第 9 万步见顶、此后小幅回落。
自博弈只产生一种结局时，新数据里几乎不含「这一手会输」的信息 ——
价值头没有可学的对比，策略头的改进目标也随之变窄。
**继续训练不涨棋力，很可能不是模型容量到顶，而是数据没有信息量了。**
这是个可以证伪的判断：加大探索（提高模拟数、延长采样温度、加 Dirichlet 噪声）
如果能把先手胜率压回 0.7 附近而棋力继续涨，就说明瓶颈在数据而不在模型。

### 7.3 工程教训

**评测吃掉了 54% 的墙钟，而且根因是 bug 不是「测多了」。**
`evaluate_vs_baseline()` 当时**根本没有 `engine_threads` 这个参数**，
构造 `SelfPlayDriver` 时不传，于是吃了默认值 `1` —— 在 144 核的机器上
**单线程**跑树搜索。评测基线每手要 4096 次 rollout，
于是单次评测 200 局要跑约 23 分钟（中位 1387.8s），50 次就是 19.9 小时。

对照：同样是规则智能体之间的对局，走 `play_match` 用 128 线程，
6000 局只要 121 秒。差距就在这一个参数上。**已修复**（本次提交），
并让训练脚本把 `cfg.engine_threads` 传下去。

### 7.4 局限

- **单次运行，n=1。** 没有换种子重跑，方差没有排除。
- **两方不能设不同的模拟数。** 批量对局路径两方共用一份 `MctsConfig`
  （C++ 的 `SelfPlayEngine` 只接受一份），所以「A 用纯策略、B 用 800 次模拟」
  这种非对称配置测不了。纯策略本身已经支持（`simulations=0`）。
- **§6 是纯策略口径，而训练期间那条评测线带 128 次模拟。** 两条曲线不可直接拼接。
- **Bradley-Terry 假设可传递**，而近实力的档位之间存在不可传递性（§6.3 里
  90,230 输给 120,230 却总分更高）。单一 Elo 数字是近似。
- **绝对刻度靠一条弱边**（§6.5）：规则阶梯只留 `flat-mcts-1k`，而它对全部 20 档
  网络都是 0:400。可靠的是网络之间的排序（±8），不是绝对值（±33）。

### 7.5 下一步

按这次数据给出的优先级排（不是按工作量）：

1. **先给自博弈加探索性，再谈加宽模型。** §7.2 的判断如果成立，
   当前配置下再多训 20 万步也不会涨 —— 提高模拟数、延长
   `temperature_plies`、加 Dirichlet 噪声，都比换更大的网络先做。
   而且这条**可以先证伪再投入**：看先手胜率能否压回 0.7 附近。
2. **建立能持续区分强弱的量尺。** 规则阶梯在训练走完 20% 时就到顶了
   （§6.2），这意味着后 80% 的训练**根本没有有效的进度信号**。
   评测应当在得分率稳定超过阈值后自动换更强的锚点 ——
   历史 checkpoint 就是现成的、会随训练一起变强的对手。
3. **加宽模型。** 14.2M 在 Blackwell 上偏瘦，`dim=384/512` 是自然的下一档。
   但在 1、2 解决之前，加宽的收益无法测量。
4. **CUDA Graph / 异步自博弈。** 现在自博弈与训练严格轮流，任一阶段跑的时候
   另一类资源在闲着。
5. **评测默认给足线程。**（已修）
